# Independent portable conversion

Normal create, replace, preserved source ZIP reading and export accept portable manifest v2 only. A v1 manifest returns `PORTABLE_UPGRADE_REQUIRED`. Missing Kind on a Notion row still means Skill; it is unrelated to archive conversion. No normal command, environment variable or configuration enables historical decoding.

Build the separate operator package with `bun scripts/build-portable-converter.ts /absolute/new-package-directory`; pack/install that directory independently using ordinary npm peer resolution. It is excluded from the normal CLI build entry and package file list.

## Offline preserved input

`ntn-skills-portable-convert offline --input OLD_DIRECTORY_OR_ZIP --output NEW_DIRECTORY [--kind skill|router|prompt]` validates the exact v1 manifest, all paths, duplicate entries, main file and projection/reference types. It writes `converted.zip` and `audit.json` into a new directory outside the input. Original bytes remain untouched. Every input and output entry has a byte length and SHA-256 inventory. Explicit kind is recorded; omitted kind records `audited-default-skill`. Binary files are never decoded as text. Malformed input fails before output creation.

## Owned remote source archives

Production conversion belongs to the AH270 runner after its actual approval gate. First inventory the exact owned page set read-only, including the reported 12-page production scope; record page/database IDs, kind, raw source bundle bytes/hash, main/resources, current authored content, publication proof, Default Context, Members and ownership. This implementation does not claim those pages were inventoried or converted.

For each approved exact page:

1. If Publication is v1, use `proof-plan --input OWNED_ALLOWLIST --output NEW_PLAN` and `proof-apply --plan PLAN --expected-plan-hash HASH --ledger NEW_LEDGER --apply` in this independent artifact. They invoke the existing remote-proof converter with its exact historical source-format/audit allowlist, complete guard/readback and no-resend ledger; the isolated source interpretation host preserves original source bytes/hash. Historical proof conversion only admits Skill, matching portable v1's audited default; a different kind requires explicit evidence review. No proof bypass or force option exists. See [proof converter contract](remote-proof-converter.md).
2. Run `ntn-skills-portable-convert remote-plan --target PAGE_UUID --database DATABASE_UUID --kind skill --output NEW_PLAN_JSON`. Planning reads the current source twice, retains original snapshot file hashes/version and raw page/property/proof/credential guards, and writes no remote state. Source archive interpretation is selected only in this independent operator host; raw downloaded archive bytes remain the version/proof input.
3. Review the plan, all authored files/resources and page scope, then compute SHA-256 of the exact plan bytes. Run `ntn-skills-portable-convert remote-apply --plan PLAN --expected-plan-hash HASH --ledger NEW_ATTEMPT_JSON --apply` only after the production gate. Apply rereads the complete current source and guards; any changed content/version/identity rejects. It durably installs an exclusive attempt with its allocated publication operation ID before calling the same `replaceSkill` publication use case as the CLI. That use case owns exact target/version validation, mutation intents, source uploads, preservation of other properties and final v2 publication proof/readback.
4. Read the current page with the normal strict CLI and verify full main/reference/binary inventory. Retain plan, attempt and normal operation receipt. Recover with the original files using `remote-reconcile --plan PLAN --expected-plan-hash HASH --ledger ATTEMPT --expected-page PAGE_UUID`, followed by the same flags on `remote-resume --apply`. Reconcile makes no remote writes. Only a known-root replacement with zero mutation intents and unchanged original inventory, credential, metadata, version, source proof and intended output can return `needs_prepare_revalidation`; resume revalidates those bounds and continues the original operation on the same page. Any pending, unknown or failed mutation request, including an uncertain page/upload allocation, returns `NO_REPLAY` through this tool. If all requests were acknowledged and the original integrity intent is bound to the same root, the tool delegates to existing core publication reconcile/resume under its isolated source decoder. It never replaces those guards with the original pre-mutation plan. A known pending upload reuses its acknowledged upload ID; expired/failed artifacts do not cause automatic allocation. Completed operations return their retained verified result without another write.
5. Historical attempt files without an operation ID require an explicit `--operation-id ORIGINAL_OPERATION_ID` on recovery. The typed core recovery use case must first prove exact page/source/scope, frozen content hashes and original integrity intent before the tool durably adds that identity to the existing ledger. It never searches by name, creates a replacement ledger or allocates a second operation. A mismatch or missing receipt stops recovery. Old cache/operation records that cannot be proved retain the independent migration's public review envelope, never execute old payloads.

Recovery consumes the approved output bytes exactly and verifies their hashes against the original publication receipt and retained intended-content hash. A newer converter's Markdown/frontmatter formatting is not allowed to rewrite that frozen authorization. New apply still reconstructs and checks its complete current source output; recovery after acknowledged mutations uses the core engine's retained post-mutation guards.

Publication continuation compares actual Notion readback through the same Markdown materialization used by consumers. A quote followed by an independent paragraph or list can require a separator omitted by Notion's Markdown response. Restoration requires complete ordered block evidence, a stable page revision and a unique text mapping; plain Markdown alone cannot authorize splitting a legal lazy quote continuation. Missing or ambiguous evidence preserves the conflict. Structural evidence participates in new snapshot versions, while original source ZIP bytes, reviewed output and retained receipt guards remain unchanged.

A completed whole-page Markdown replacement can cover an earlier acknowledged block repair on that same page after the writer retires obsolete block guards. Reconciliation must trace the earlier repair's saved parent chain, prove the later full replacement and its current body against all retained guards, and validate the complete original publication journal. Pending writes, another page's replacement, partial updates or an incomplete ownership chain cannot provide coverage. The read-only result identifies both intent indices; original intent status, response and guards remain audit history, and the covered repair is not replayed.

A failed References write formally reconciled as `known_not_applied` remains failed audit history. A later completed replacement of the same native rich-text property can cover its obsolete value only when the complete frozen reference inventory, acknowledged child allocations, current property, bodies and retained guards all verify. Reconciliation records the covering intent and does not trust an old replay pointer as mutation authority. Known root and child creates use their unique original completed POST acknowledgements, exact page IDs, parents, markers and reference bindings; uncertain allocations still require creation-correlation proof. Deferred References retries do not claim a future intent index before their actual replacement is dispatched.

When a previously reviewed plan has never installed an attempt, an operator can explicitly request a current-baseline successor with `ntn-skills-portable-convert remote-replan --from-plan ORIGINAL.json --expected-plan-hash OLD_SHA256 --ledger ORIGINAL_ATTEMPT_PATH --preserve-output`. This performs remote reads and returns a new JSON plan on stdout; it never edits the original plan. Its `portable-remote-reviewed-upgrade` format retains the complete original plan bytes, SHA-256 and attempt path in `lineage`, captures the actual current snapshot and preserves every reviewed output byte. It rejects an existing original attempt or a retained same-page/scope publication, an unchanged materialization version, or any change to raw source, metadata, proof, references, ZIP or resources. Only the proved generated entry name representation may differ.

Review the successor separately, then use `remote-apply --plan NEW.json --expected-plan-hash NEW_SHA256 --ledger NEW_ATTEMPT_PATH --apply`. The new attempt path must differ from the original, which must still be absent. Existing attempts continue through their original reconcile/resume contract and cannot use replan to escape their guards. Normal CLI source interpretation remains strict current v2; this independently packaged operator carries the historical input and explicit lineage contract.

When an existing known-root operation has zero mutation intents but its original snapshot was generated by an older materialization revision, use the independent tool's explicit recovery review instead of creating another plan or operation:

```bash
ntn-skills-portable-convert remote-recovery-plan --plan ORIGINAL.json --expected-plan-hash ORIGINAL_SHA256 --ledger ORIGINAL_ATTEMPT --expected-page PAGE_UUID --operation-id ORIGINAL_OPERATION_ID
```

This read-only command returns a `portable-remote-recovery-review` JSON document. Save those exact bytes and review their SHA-256. It binds the complete original plan/hash, absolute original ledger path and ledger-byte hash, original operation/page, unchanged output and an actual current snapshot. The public core recovery gate must prove zero mutation intents, an unbound integrity page and a writing marker. Raw metadata, credential/proof guards, complete References, source ZIP and resource hashes must remain equal; only generated entry naming and materialization snapshot/version fields may differ.

Resume that same operation with the original plan and ledger plus `--recovery-plan REVIEW.json --expected-recovery-plan-hash REVIEW_SHA256 --apply` on `remote-resume`. The tool rechecks the review hash, original operation/ledger hash, complete current authority and the reviewed current version before the core accepts the continuation baseline. It preserves historical receipt bounds and executes the existing publication using that current baseline's strict version guard. Wrong operation/ledger, changed authored content/metadata/resources, forged current baselines, or any mutation intent reject this branch. Pending or unknown writes must use the existing reconciliation path; a recovery review cannot authorize their replay. Normal runtime callers do not enable materialization-version continuation.

The portable converter never PATCHes Notion directly; its proof commands retain the proof converter's sole guarded Publication-property write. Neither path clears Files nor substitutes offline bytes for newer user edits. `remote-plan` accepts an explicitly selected unmanaged page with an empty Publication property and binds that exact state in its reviewed guard. Applying the unchanged plan republishes the reviewed content on the same page and creates a current proof. `proof-plan` instead requires an existing committed historical proof; it cannot enroll unmanaged pages. Changed source or guards reject apply.
