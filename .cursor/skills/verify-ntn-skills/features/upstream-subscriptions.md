# Upstream subscriptions: fixed sources, accepted deltas and published Router

This recipe exercises the installed `ntn-skills sync upstream` official CLI tree. Record CLI/version/hash, Effect exact version, separate config/state/cache roots, exact native content/subscription database and data source IDs, operation IDs, saved plan hashes, page IDs and pinned resource refs. Use an owned temporary Git repository and owned test Notion tables; the actual Agent Kit checkout and its tracked contents remain read-only.

Prepare one source containing two complete Skills, references, script, lock file and a binary asset. Start through `sync upstream connect SOURCE --database CONTENT_DATABASE`: default Git ref is `HEAD`, root is `.`, and include/exclude patterns select member directory paths. Verify a complete initial run, then repeat the same connection and require the same subscription with its saved name/configuration. `sync upstream list` returns `{ok:true,items:[...]}`.

Advanced registration coverage uses `sync upstream add --input <configuration.json> --operation <stable-id>` with strict target_database_id/name/description/default_context/enabled/source/roots/include/exclude/mapping. `source.provider` is Git, registry or GitHub marketplace as described by actual help. Source patch/path/shared-target options remain advanced configuration; ordinary Git connection does not require hand-authored internal JSON.

Run `sync upstream check <subscription-id>` as metadata-only observation: retain subscription/member metadata and Publication markers without fetching Git/registry source files, member bodies or raw/adapted hashes, and without advancing accepted baselines. Then run `sync upstream plan <subscription-id>`; plan/apply own the resolved commit, complete source files and raw/adapted hash evidence. Save the plan ID. Advance the Git branch before `sync upstream apply <saved-plan-id>`: the result must publish the saved candidate or reject stale target preconditions, and must never silently fetch a replacement plan. Read the automatic Router through `skill://upstream%3A<subscription-id>/ROUTER.md`, select its exact member ref and export its pinned snapshot from an independent empty-cache consumer. Compare binary bytes and complete inventory. Repeat the same revision: no duplicate member page or content replacement. `sync upstream run` without either `--target` or `--all`, or with both, must fail. No scheduler may appear.

Exercise zero, one and two verified published active members. Zero/single-member subscriptions must have no automatic Router catalog/completion entry and their current exact Router read must fail with `UPSTREAM_ROUTER_UNAVAILABLE`; a single member must remain independently discoverable/readable with its upstream namespace. Two members must retain a usable Router whose index includes both exact refs. Status/check must agree with discovery and current reads without treating a successful single-member sync as failed. Seed a pre-upgrade Router observation: it must not bypass the minimum through TTL/offline reads, while pinned history stays readable. Verify manually authored Routers still accept explicitly empty or single-member relations.

Advance the source to add a member, update one resource, remove another member and exclude a previously active member. Run and verify exact original page identity for updates, new identity for additions, retained content for missing/excluded members, and their absence from the automatic active roster. Rename a Skill or introduce a name collision: verify explicit conflict and no guessed identity match. Edit tracked managed content directly in Notion and verify plan/apply stop with conflict while Default Context, manual Router Members and organizational fields remain intact.

For deletion recovery, put one owned tracked member in Notion Trash and use ordinary `sync upstream run --target SUBSCRIPTION_ID`. Require a distinct committed native page with complete source files, the old page still in Trash, and only that member mapping changed. Repeat run after publication or map-write interruption: continue the same retained work without duplicate pages or replay of an unconfirmed map PATCH. Missing/inaccessible pages, foreign owners and moved databases remain failures rather than deletion evidence; a fork or excluded source member is not restored. A live page must not enter the deletion-recovery path. Record installed CLI and live Notion results separately.

Fork the edited member explicitly. Verify Fork Baseline contains original ref, fixed revision, hash and a remotely recoverable baseline reference. Retrieve that baseline using the public reader in a separate state root and verify full files. Later source updates must preserve the fork. `sync upstream track <id> <member-key>` returns differences until manually resolved; it must not force replacement or auto-merge. Disable subscription with versioned update: old published entry remains readable and automatic updating stops. Remove subscription with `--if-version`: automatic entry disappears, member pages remain.

Use two owned sources in one shared_target_set with an explicit unique publisher and independent accepted_ref. Source B changes file B after source A's file A is already accepted. Applying B must preserve A's bytes, use the same page, and update materialized hashes in previously published Router projections without advancing A's source accepted_ref/revision/plan_hash/active roster. Change the same file differently in both sources and verify conflict. Interrupt between target verification and Router projection updates; status must show pending/partial/unknown projection entries. Resume the same plan and confirm exact-document reconciliation. Manually change an affected published map and verify it is preserved as conflict.

Exercise ClawHub protocol against an owned controllable registry: resolve latest to a specific version, download its full manifest, verify declared file sizes/hash and binary assets, and fail on hash mismatch or version mismatch. Exercise a skills.sh GitHub-backed source and inspect provenance to prove Git acquisition is reused. Apply the actual Cloudflare-style version-one exact replacement patch, retain original revision/upstream hash plus patch/adapted hash, and change a patch expectation so it no longer occurs exactly once: no content publication is allowed.

Exercise a complete Published Members JSON document between 180000 and 200000 characters through the native subscription publisher. Require exact readback of every source/member identity with no more than 100 spans of at most 2000 characters; a partial subscription must not drop pending manifest members to fit.

Inject an unknown create response after the remote write and resume the same add/publication operation. Verify operation-marker reconciliation, no duplicate page and no replay of an unproven create. Inject a failure on one member while another completes: only verified member baselines may advance, and operation must remain partial/unknown. Start two real CLI processes against the same local state/target and verify only one generation advances. Preserve all receipts and actual fault trigger; a controlled boundary is separate evidence from real Notion and UI.

For recurring synchronization, upgrade existing owned tables through `ctl database init` with a new operation ID and verify the native select/date/date/rich-text types of `Sync Status`, `Last Sync Attempt`, `Last Synced` and `Sync Summary`. Run a successful source and repeat it unchanged: both must finish successfully and refresh the last successful time, while the unchanged run performs no member content publication. Fail source acquisition after success and introduce a managed-content conflict; failed/partial outcomes must preserve the previous successful time. Compare dates at Notion's native minute precision, accepting timezone normalization rather than requiring clock milliseconds to survive the API.

Run an unavailable source before a valid source in one installed CLI batch. Require the valid source to finish, summary counts to match every selected target and exit 1 with `UPSTREAM_SYNC_INCOMPLETE` and per-target results in `error.details`. All-success runs must exit 0. Verify that final status-write failure reports `status_error_code` without claiming content rollback. Start overlapping runs of the same subscription against one state root and require the overlapping target to return `SYNC_LOCKED` without overwriting the holder's workflow fields.

For origin acceptance, explicitly initialize content Source Type select (builtin/upstream/manual) and rich-text Builtin ID, including repeating an already-published attach. Require preflight before upstream mutation and raw Notion readback of upstream with empty Builtin ID. Fork/tracked changes Sync Mode independently and retains upstream origin. Equal-content source correction is metadata-only; complete equality is mutation-free reuse. The [publication recipe](import-create-recovery-dry-run.md) owns frozen source/property-ID recovery and legacy unset preservation; public record JSON is unchanged. These cases leave the automatic Router minimum of two active published Skills intact and claim no live pass.


Local prerequisites already available: `packages/core/test/upstream-source.test.ts` uses real temporary Git and local registry HTTP inputs; `upstream.test.ts` covers shared deltas/strict active maps and actual frozen AK census; `upstream-state.node.test.ts` uses official SQLite plus two real Node processes. These tests do not prove real Notion publication, installed CLI delivery, independent snapshot consumption or Pi/OMP model behavior. Run real Notion and dual-host checks with the designated e2e role and record each evidence class separately.

A live content-database `list --database CONTENT --refresh` must return `records` and must not include `skills`. Broker discovery rejects a `skills` payload before any `$` candidate exists. Subscription Router rows belong to the upstream database and are not member Skills. For each enabled subscription, every included source member must have its own content-database skill page; a Router alias does not satisfy that check. `resin` is a content page (`3fb5636c-236e-814e-8f88-e4e8e00f051a`) and is not an upstream subscription. Pending subscriptions with an empty published manifest have not landed their repo skills. `sync upstream run` plans and applies each selected subscription independently and keeps a per-subscription error instead of substituting another plan.

## Historical operator coverage

These retained editable-file cases apply to changes in the independent operator artifact, not as prerequisites for ordinary connect/run.

For frozen pending text members, exercise `ntn-skills-operator upstream publish-files PLAN MEMBER --operation NEW`, then its returned selected apply. Verify the committed content page and accepted published-map entry separately. Complete literal-file readback, not the generic rendered-Markdown journal, owns reconciliation. An unknown terminal append never becomes failed merely because reads are absent; explicit `--supersede OLD` allocates a distinct page, retains old unknown effects and rejects changed ownership/frozen source or an accepted target. Include independent-state Agent-facing read/resource/export evidence; metadata listing alone is not body proof.

Refuse changed page/source, other fields/pages, create/append/upload and `--new-artifact`; ordinary resume must remain no-replay. An interrupted pre-send certificate must still require fresh proof on continuation. Accepted parent mapping and independent consumer readback remain separate checks.

Include a multi-megabyte text member with large files, escaped JSON and Unicode. Verify bounded initial nested allocations and later code batches (at most 100 total blocks and below 500 KB encoded JSON), fresh complete file hashes and accepted map identity. A lost batch response must remain unknown unless the entire ordered intended tree is observed; suffix continuation must preserve bytes from earlier chunks without duplication.
