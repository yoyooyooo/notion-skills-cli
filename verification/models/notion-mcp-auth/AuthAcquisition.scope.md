# Proposed design only
Two waiters share one automatic authorization transaction and start together. One credential revocation, one session change, a two-tick deadline, and at most two code exchanges are explored. Callback validation abstracts state/issuer/PKCE/resource/redirect/expiry as one predicate; their byte-level implementation is not proved. No browser, network, cryptography, persistence, or production refinement is proved. Tick, local timeout and local publication are weakly fair; browser and remote completion are not assumed. Terminal stuttering is permitted only when all requests have an explicit outcome. Events set monotone violation witnesses at the publication/commit event, so later logout does not retroactively invalidate a legitimate history. A cancelled final waiter retires this automatic flight; a proactive CLI login would own its own waiter.

Independent review correction: the v1 model fenced token commit after logout but did not fence the preceding code-exchange dispatch. v2 adds a pre-exchange credential-epoch/deadline gate and an independently declared negative case. This is a proposed-design correction, not an observed production defect. Full witness configurations intentionally reject NoSuccessfulPair/NoLocalCancelSuccess and are not counted as safety defects.

Deadline review correction: current-time checks now apply at callback exchange, grant commit, and waiter resume. Weak fairness of a future timeout is insufficient as a present-time guard. The automatic flight and its two simultaneously started waiters share one abstract two-tick deadline in this slice; arbitrarily staggered waiter deadlines and a separate proactive-login owner require implementation acceptance. v4 adds explicit expired-grant and expired-resume negative configurations.
